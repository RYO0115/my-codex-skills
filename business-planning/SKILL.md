# 事業展開計画スキル

市場調査を「で、どうするか」に変換するスキル。出力は常に、数字と担当と期限を
伴った**実行可能な計画**であること。方法論は `references/` に機能別に分割してある。
必要になったステップで該当ファイルだけを読むこと。

| 機能 | 参照ファイル |
|---|---|
| 事業モデル設計(リーンキャンバス・Ansoff・STP) | [references/frameworks.md](references/frameworks.md) |
| GTM戦略(ICP・ポジショニング・チャネル・価格) | [references/gtm-strategy.md](references/gtm-strategy.md) |
| 数字(ユニットエコノミクス・財務計画・KPIツリー) | [references/financials.md](references/financials.md) |
| リスク分析・ロードマップ・OKR | [references/risk-and-roadmap.md](references/risk-and-roadmap.md) |
| 海外展開・新市場参入 | [references/market-entry.md](references/market-entry.md) |
| 計画書雛形と品質ゲート | [references/plan-template.md](references/plan-template.md) |

## 役割分担(必須)

- **統括(このセッションのメインモデル)**: ヒアリング、モード選択、戦略判断
  (どのセグメントを捨てるか・何をやらないか)、サブエージェント結果の統合、
  計画執筆、品質ゲート判定。**戦略的トレードオフの判断はサブエージェントに
  委譲しない。**
- **裏付け調査担当(Codex サブエージェント)**: 競合の価格実勢、チャネル別の
  相場(CAC 目安)、規制・参入要件、ベンチマーク企業の事例収集など、個別の
  事実確認。利用可能な multi-agent ツールで独立タスクを並列実行する。
  モデルは原則として親から継承し、必要な場合だけ明示的に上書きする。指示には market-research スキルと同じ
  出典ルール(URL+一次/二次の別+反証+未発見は未発見と報告)を含める。

## ワークフロー

### Step 0 — 入力確認と診断ヒアリング

1. `knowledge/research/<slug>/` に market-research の成果物(`market-research-*.md`,
   `context.md`)があれば読み込み、前提を引き継ぐ。**無ければ先に市場調査を
   勧める**(最低限、対象市場・競合・顧客の根拠なしに計画は書かない)。
2. 不足情報が計画を大きく変える場合だけ、ユーザーへまとめて確認(最大2回):
   事業ステージ / 使えるリソース(人・金・期間)/ 成功の定義(1年後に何が
   達成できていれば成功か)/ 制約(やらないと決めていること)。

### Step 1 — モード選択

対象に応じて出力モードを選ぶ(判断が必要ならユーザーへ提示し、明白なら提案して進む):

- **リーン計画(1枚)** — アイデア検証段階。リーンキャンバス+検証計画。
- **フル事業計画** — 投資判断・稟議用。市場分析〜財務予測〜ロードマップまで。
- **GTM計画** — 製品はあり、売り方を決める段階。
- **参入計画** — 既存事業の新市場展開(海外含む)。Ansoff で方向を先に確定。

### Step 2 — 並列裏付け調査(Codex subagents)

計画の骨子を統括モデルが先に仮決めし、**仮説の裏付け・反証に必要な事実だけ**を
サブエージェントに取りに行かせる(調査の丸投げをしない)。典型的な分割:

- 価格・ユニットエコノミクス担当: 競合価格、チャネル別 CAC 相場、業界の解約率
- チャネル・事例担当: 類似企業の GTM 事例(成功・失敗の両方)
- 規制・参入要件担当(参入計画のみ): 許認可、現地規制、JETRO 資料

### Step 3 — 計画統合

- 数字は [financials.md](references/financials.md) の形式で、全て前提付きで組む。
  LTV:CAC 等の健全性チェックに通らない計画はそのまま出さず、価格・チャネル・
  ターゲットのどれを直すかまで踏み込む。
- **プレモーテム(削除不可)**: 「1年後にこの計画は失敗した」と仮定して失敗
  要因を列挙し、上位 3 つに事前対策を付ける([risk-and-roadmap.md](references/risk-and-roadmap.md))。
- 前段の成果物を必ず参照する一方向パイプラインを守る:
  市場調査 → セグメント選定 → ポジショニング → チャネル/価格 → 財務 → ロードマップ。

### Step 4 — 出力と品質ゲート

[plan-template.md](references/plan-template.md) の該当モードの雛形で
`knowledge/research/<slug>/business-plan-YYYY-MM-DD.md`(モードにより gtm-plan / entry-plan)
に出力し、品質ゲート(曖昧さテスト・数字の整合・プレモーテム有無・90日プランの
実行可能性)を自己チェックしてから納品する。`context.md` に決定事項を追記する。
書き出した/更新した各ファイルの末尾 `## 履歴` に `- <今日>: <何をしたか1行>` を
時系列で追記する(新規は `初版作成`)。
