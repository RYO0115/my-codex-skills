# 数字まわり(ユニットエコノミクス・財務計画・KPIツリー)

計画中の数値は全て「前提付き」で書く。前提のない数字は品質ゲートで落とす。

## ユニットエコノミクス

- **入力**: 価格(gtm-strategy で決めた仮説)、チャネル別獲得コスト、想定解約率、粗利率。
- **出力**:

```
CAC  = 獲得コスト合計 ÷ 獲得顧客数(チャネル別に出す)
LTV  = 平均月次粗利 × 平均継続月数(≒ 月次粗利 ÷ 月次解約率)
LTV : CAC ≥ 3 : 1        … 健全ラインの目安
CAC 回収期間 ≤ 12ヶ月     … SaaS の目安(業態により調整)
```

- 検算に通らない場合、計画をそのまま出さない。価格を上げる / チャネルを変える /
  ターゲットを絞る(解約率の低い層へ)のどれで直すかを明記する。
- ベンチマーク値(業界の解約率・CAC相場)はサブエージェントに出典付きで
  収集させ、自社推定と併記する。

## 売上予測と損益分岐

- **売上予測はボトムアップで組む**(市場規模×シェア%のトップダウンだけの予測は
  禁止 — 「1%獲れば」は計画ではない):

```
月次売上 = 有効リード数 × 商談化率 × 受注率 × 平均単価
(各係数に根拠: 実績 / 業界ベンチマーク / 仮置き のラベルを付ける)
```

- 悲観 / 標準 / 楽観 の3シナリオ。悲観シナリオでも資金が尽きないかを確認する。
- 損益分岐: 固定費 ÷(単価あたり限界利益)で必要顧客数を出し、到達月を
  ロードマップに載せる。

## KPI ツリー / North Star Metric

- **North Star Metric は1つ**: 顧客が価値を受け取った量を表す指標
  (売上そのものではなく、売上に先行するもの。例: 週次アクティブ利用、処理件数)。
- NSM を先行指標に分解してツリー化し、90日ロードマップの各施策を
  ツリーのどのノードを動かすものかに対応付ける。
- 遅行指標(売上・解約率)と先行指標(リード数・活性化率)を区別し、
  日々見るのは先行指標にする。

## 出力形式

財務まわりの表は計画書内に Markdown 表で埋め込み、係数の前提を表の直下に
箇条書きで付ける。スプレッドシート化が必要な規模なら、その旨と構成案だけ
書いて計画書を肥大化させない。
