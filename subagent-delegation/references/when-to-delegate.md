# 委譲判断

次の条件をすべて満たす場合だけ委譲する。

1. ユーザーまたは適用中の規約がサブエージェント利用を許可している。
2. タスクが独立しており、親が結果を待たずに統合準備など別の有益な作業を進められる。
3. 目的、対象範囲、成果物、禁止事項、検証方法を短い指示で閉じられる。
4. 書き込み範囲が親や他エージェントと重ならない。
5. 起動・説明・レビューのコストを、並列化または文脈圧縮の効果が上回る。

委譲先はCodex native agentとClaude Code CLIから選ぶ。Claudeでは仕事の性質に応じて
Opus / Sonnet / Haikuのaliasを使い、実行前にCLIとモデルが利用可能か確認する。利用不可や
上限到達時はCodex native agentまたは親へ戻す。

委譲しやすい例:

- 4つの市場観点を独立して調査し、各結果を表形式で返す
- 20ファイルへの同じ機械変換を、親と重ならない範囲で適用する
- 担当者が実装中に、別エージェントが仕様との不一致だけを調べる

## Claudeモデル選択の追加テスト

ROIテストを通った後、次のうち最も安い十分なモデルを選ぶ。

- **Opus**: 選択肢が複数あり、誤ると広範囲へ波及する計画・設計・高リスクレビュー。
- **Sonnet**: 受入条件が明確だが、コード理解・取捨選択・自己修正が要る実装や検証。
- **Haiku**: 正解が一意で、失敗を機械チェックできる、まとまった単純作業。
- **委譲しない**: 1コマンド、短い確認、強い会話文脈依存、最終意思決定。

「簡単だからHaiku」ではなく、**cold startを回収できるだけの量があるか**も見る。Haikuが
2往復必要になりそうなら最初からSonnetを使う。Opusで計画した後に同じ調査をSonnetへ
繰り返させず、計画と根拠パスだけを実装ブリーフへ渡す。

委譲しない例:

- 次に編集する関数の仕様確認
- 1ファイルの小修正
- ユーザーの曖昧な意図を確定する判断
- 同じテストを親とサブエージェントの両方が実行する二重確認
