# 着手前トリアージでトークンを削る(task-triage)

トークンが無駄になる典型は2つ。**軽いタスクへの過剰装備**(1行の質問に広域 grep・
ファイル全読み・subagent 起動)と、**重いタスクへの無計画突入**(見通しなく読み始めて
同じファイルを何度も読み直す・手戻りする)。どちらも「作業の重さを見積もる前に
手を動かした」ことが原因。**先に30秒ぶんの見積もりをして、実行モードを固定してから
動く**のがこのスキルの全体像。

## Step 1 — 難易度を見積もる(ツールを叩く前に)

最初のツール呼び出しの**前に**、指示文と既知の文脈(CLAUDE.md・会話履歴・直前の作業)
だけで次の3軸を判定する。**見積もりのための探索はしない**(見積もりが高くつくと本末転倒)。

| 軸 | 軽 | 重 |
|---|---|---|
| **範囲** | 触る/読むファイルが1〜2個で場所も分かっている | 対象が複数箇所・場所の特定から必要 |
| **曖昧さ** | 何をもって完了か明確 | 完了条件・方針に判断の余地が大きい |
| **検証** | 目視/1コマンドで確認できる | テスト・実行・複数手順の確認が要る |

3軸の多数決でクラスを決める:

- **軽** — 一問一答、既知ファイルの小修正、定型の1操作(スクリプト実行など)。
- **中** — 数ファイルの改修、特定済みバグの修正、1本のドキュメント/記事作業。
- **重** — 場所探しから始まる改修、新規機能・新規スキル作成、大量の機械作業、
  複数プロジェクトにまたがる作業。

迷ったら**軽い方に倒す**。Step 3 の昇格ルールがあるので、軽く始めて足りなければ
上げればよい。逆(重装備で始めて後から気づく)は使ったトークンが戻らない。

## Step 2 — クラスに応じた実行モードを固定する

### 軽:即答モード
- **探索禁止**。既知の文脈で答える/直す。読むとしても該当ファイルの必要箇所だけ
  (`rg` で位置を絞り、`sed` 等で必要な行だけ読む)。
- subagent・計画立案・進捗管理は使わない。回答も簡潔に。

### 中:限定読みモード
- 触るファイルを**先に列挙**してから読む。読み終わったファイルを読み直さない
  (必要箇所をその場で把握してから編集に入る)。
- 検索は絞ったパターンで1〜2回。広域 fan-out はしない。
- 独立なツール呼び出しは**1レスポンスに並列**でまとめる(往復回数=コンテキスト再送回数)。

### 重:計画→分割モード
- 手を動かす前に**手順を数行で確定**する(何を読み、何を作り、何で検証するか)。
  読み直し・手戻りを防ぐのが目的で、計画自体は短くてよい。
- 「中間出力が大量で成果物が小さい」部分(広域探索・大量の定型編集・長文の読解要約)は
  [subagent-delegation](../subagent-delegation/SKILL.md) の ROI テストにかけ、通るなら
  Codex の subagent に切り出す。モデルは原則として親から継承し、ユーザー指定または
  明確なタスク上の理由がある場合だけ上書きする。通らなければ自分でやる。
- 大きなファイルは全読みせず、目次的に眺めてから必要区間だけ読む。

## Step 3 — 見積もりを宣言し、外れたら1回だけ組み替える

- 作業開始時に、見積もりと選んだモードを**1行**でユーザーに示す
  (例:「軽と見て直接修正します」「重なので手順を固定し、探索は subagent に出します」)。
  長い前置きはそれ自体がトークンなので1行厳守。
- 作業中に前提が崩れたら(軽のつもりが対象が5ファイルに増えた等)、**その場で1段階だけ
  昇格**し、モードを組み替えてから続ける。ズルズルと軽モードのまま重作業を続けない。
- 降格も同様(重と見たが実は1ファイルで済んだ → 計画を畳んで即答モードで終える)。

## やらないこと(見積もりを殺すアンチパターン)

- **見積もりのための探索** — 判定は指示文と既知文脈だけで行う。30秒で決める。
- **見積もりの儀式化** — 明白に軽いタスク(挨拶・一問一答・「さっきの続き」)に
  宣言や表判定を持ち込まない。黙って即答してよい。
- **保険の先読み** — 「使うかもしれない」ファイルを先に読んでおくこと。使うと
  確定してから読む。
- **同じファイルの再読** — 編集直後の確認読み・読んだ内容の読み直し。ハーネスが
  ファイル状態を追跡している前提で動く。
- **軽タスクへの subagent** — cold start コストで確実に損する(詳細は
  subagent-delegation の ROI 基準)。
